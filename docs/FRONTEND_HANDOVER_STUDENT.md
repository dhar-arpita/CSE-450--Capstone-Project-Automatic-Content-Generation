## 2. Running it

```bash
cd frontend
npm install
npm start                 # http://localhost:3000
```

Create React App 5 (`react-scripts`), React 19, **plain JavaScript**. No
TypeScript, no Tailwind, no component library, no CSS-in-JS. Don't add one — the
project is small and graders read the source.

Cold compiles take 4–6 minutes on a modest laptop. Wait rather than restarting.

The backend defaults to `http://127.0.0.1:8000`; override with `REACT_APP_API_URL`.
Backend setup is in `PLATFORM_OVERVIEW.md` §13. You can do most layout and
styling work without it — pages render and fail gracefully — but the chatbot is
genuinely hard to develop blind, so get the backend running before you start §11.

## 3. The product, in a paragraph

Dhi (**ধী** — intellect) turns a chapter of the Bangladeshi national curriculum
into classroom material. Teachers generate worksheets, quizzes and study notes.
**Students get a practice companion**: they pick a subject and chapter, then ask
questions, work through practice problems one at a time with hints instead of
answers, or take an MCQ quiz. The whole thing works in Bangla or English.

Your half is the student-facing half of that. The emotional brief for it is
*the patient tutor at 11pm when there is nobody at home to explain it again* —
that is literally the copy on the landing page, and it should guide every
decision you make about tone, pacing and error states.

Generation is slow (retrieval + LLM), so **heavy work runs as a background job
the frontend polls** — see §12.

## 4. The design language: forest + bubblegum

This is the part people notice first. Two families:

- **Forest** — deep greens on warm off-white paper. It carries structure: page
  backgrounds, body text, borders, primary buttons, dark panels. The calm,
  serious, editorial half.
- **Bubblegum** — a hot pink. **Emphasis only**: eyebrows above headings, the
  focus ring, the student-side primary button, small accents. Never a background
  for a large area, never a second body colour.

Plus the **logo palette** — the six flat colours of the tangram bird (violet,
leaf, petal, sky, sun, coral). Illustration and brand moments only, not UI chrome.

The student surfaces lean **warmer and more playful** than the teacher ones —
that is why the student login button is bubblegum pink while the teacher's is
forest-dark. Playful within the system; not a different system.

**`--dhi-solid-bg` / `--dhi-solid-fg` is the important pair.** It inverts between
themes on purpose: a filled button is near-black on cream in light mode and
near-white on near-black in dark mode, so it always reads as *the solid thing on
the page*. Use it for primary actions and dark mode comes for free.

### The rule that keeps dark mode working

> **Never write a literal colour in a component.** No `#fff`, no `#0f172a`, no
> `rgba(0,0,0,.08)` — not in a `style={{}}`, not in a `.css` file.

Every colour comes from a token. If you need one that has no token, add it to
`tokens.css` **with both a light and a dark value**, and name it semantically
(`--dhi-surface-sunken`, not `--dhi-grey-100`).

The only exceptions in the codebase are permanently dark decorative panels where
a colour is part of an illustration, and the pinned logo wordmark (§10). Both are
commented where they occur.

### What is explicitly rejected

This project's owner has a specific and firmly held bar. Work that looks like
this gets thrown out:

- ❌ **Multi-stop gradients as decoration** — `linear-gradient(135deg, #4f46e5, #6366f1)`
  on a button or an icon tile. A single soft gradient used for *depth* (a night
  sky, a vignette) is fine; a gradient used because flat felt boring is not.
- ❌ **Glassmorphism blobs** — floating translucent circles with `blur()`.
- ❌ **Emoji standing in for icons.** 🎓 📝 ⚡ 🎯 📋 in a card, a button or a
  heading is the single clearest tell that something was not designed. Use the
  SVG set in `src/features/auth/icons.js`, or draw new ones in the same style:
  24×24 viewBox, `fill="none"`, `stroke="currentColor"`, `stroke-width: 1.7`,
  round caps and joins.
  **This matters more for you than for anyone else on the team** — the chatbot is
  the most emoji-saturated file in the repo, including emoji baked into the
  translated strings themselves (see §11).
- ❌ **Generic SaaS copy.** "Everything you need, nothing you don't",
  "Supercharge your learning", "Unlock the future". Placeholder writing is
  treated as a failure of craft, not a detail to fix later. See §7.
- ❌ **Purple/indigo `#4f46e5`** and the per-page accent colours (`#0891b2`,
  `#db2777`, `#7c3aed`, `#059669`). That was the old palette; it is being removed.
- ❌ Drop shadows with a coloured tint (`0 20px 50px rgba(79,70,229,.15)`).

### What is wanted instead

Cinematic and editorial. The supplied references were full-bleed video heroes,
minimal floating nav pills, large centred typography mixing a serif display face
with a sans body, restrained pill buttons, generous whitespace, and **line-art
illustration rather than stock graphics or emoji**.

Study these before designing anything — they are the built reference:

```
src/features/auth/LoginPage.js + AuthShell.js  variant="student"   ← your closest model
src/features/auth/auth.css                     the form/button/field scale
src/features/auth/scenes.js                    how illustration is drawn here
src/features/landing/LandingPage.{js,css}      section rhythm and the hero
```

The student login page is the single best reference for the mood you are
extending: a split screen, a deep night panel with a constellation of hand-drawn
line glyphs and the tangram bird riding a dotted flight path, a scalloped seam
between the light and dark halves, and a bubblegum button.

## 5. Typography

Loaded in one request at the top of `src/shared/styles/index.css`.

| Role | English | Bangla |
|---|---|---|
| Body / UI | **Inter** | **Hind Siliguri** |
| Display / headings | **Instrument Serif** | **Tiro Bangla** |

Use `var(--dhi-sans)` and `var(--dhi-display)`. `tokens.css` already swaps both
families under `html[lang="bn"]`, so you write the rule once.

**Bengali typesetting rules.** Getting these wrong is the fastest way to make
Bangla look machine-made:

- **No `letter-spacing`.** Tracking breaks conjuncts (যুক্তাক্ষর). Where a Latin
  eyebrow uses `letter-spacing: .15em`, the Bangla override resets it to `0`.
- **No `text-transform: uppercase`.** Bengali has no case; it does nothing, and
  the tracking that usually comes with it damages the text.
- **More leading.** Matras sit above the x-height and descenders below. A heading
  at `line-height: 1.06` in English needs about `1.34` in Bangla.
- **Display accent stays upright.** `<em>` inside a heading is italic in
  Instrument Serif but must be `font-style: normal` in Tiro Bangla — a faux
  oblique on Bengali looks broken.
- Bangla renders visually larger at the same `font-size`. Tune per component.

The pattern used throughout:

```css
.au-eyebrow { text-transform: uppercase; letter-spacing: .15em; font-size: .7rem; }
html[lang="bn"] .au-eyebrow { text-transform: none; letter-spacing: .01em; font-size: .84rem; }

.au-title { line-height: 1.06; letter-spacing: -.02em; }
html[lang="bn"] .au-title { line-height: 1.34; letter-spacing: 0; }
```

This matters doubly in a chat interface, where Bangla and English often sit in
the same sentence — mixed-script lines need leading set for the Bangla, not the
Latin.

## 6. Internationalisation

The whole app is bilingual, **Bangla first**.

```js
import { useI18n } from "../../shared/i18n";

const { t, lang, setLang, toggleLang } = useI18n();
t("auth.fields.email")       // "ইমেইল" or "Email"
t("auth.student.points")     // returns the array — map over it
lang                         // "bn" | "en"
```

- Every string lives in
  [`src/shared/i18n/strings.js`](../frontend/src/shared/i18n/strings.js) as two
  parallel objects, `bn` and `en`. Add to **both**.
- `t()` takes a dot path and falls back `bn → en → the key itself`, so a missing
  translation shows up on screen as `auth.fields.email` rather than blank. If you
  see a dot path in the UI, that is the bug.
- **There is no interpolation.** No `t("greeting", { name })`. When a sentence
  needs a variable, compose it in JSX from two keys — or, better and what the
  existing code does, store one key per case.
  `auth.errors.wrongRole.student` / `.teacher` / `.admin` exist as three separate
  sentences precisely so each reads naturally in Bangla, where word order differs.
- The choice persists in `localStorage` under `dhi.lang` and sets `<html lang>`,
  which is what drives every `html[lang="bn"]` rule above.
- **Bangla is the default** (`DEFAULT_LANGUAGE = "bn"`).

### The trap that will bite you on the chatbot

`ChatbotPage.js` carries its own private string table and its own language state:

```js
const [language, setLanguage] = useState("bangla");   // ← not "bn"
const t = TXT[language] || TXT.bangla;
```

and **that same value is also sent to the backend** — `useChatSession({ language })`
puts it in every request body, where the API expects the literal strings
`"bangla"` or `"english"`.

When you migrate to the global `useI18n()`, keep the two concepts apart:

- **UI language** — `lang` from `useI18n()`, values `"bn" | "en"`. What the
  buttons and labels are written in.
- **Content language** — what the AI answers, hints and quiz questions are
  written in. Its own state, its own visible control, mapped to
  `"bangla" | "english"` at the API boundary.

A student may genuinely want an English answer while using a Bangla interface
(English-medium schools, English textbooks). Defaulting content language to
follow the UI language is a fine starting behaviour, but it must stay overridable.

## 7. Copy — treated as design, not filler

### English

Specific to this product, never interchangeable. Write about the real thing:
chapters of the NCTB curriculum, a hint instead of the answer, picking up where
you stopped. Concrete beats clever.

The landing headline is *"You teach the syllabus, now bring it to life in their
language."* That is the register — plain, warm, about somebody's actual day.

### Bangla — this is the part that goes wrong

The requirement is **প্রাঞ্জল (pranjol)**: lucid, easy-flowing, modern **spoken**
Bengali. Not formal, not literary, not translated. A previous draft was rejected
with "the bengali part is sooo machine-translated".

**Bengali speakers mix English words into everyday speech constantly, and those
words must be written in Bangla script** — not in Latin letters, and not replaced
by formal Bengali equivalents.

| Write this | Not this | (means) |
|---|---|---|
| সিলেবাস | পাঠ্যক্রম | syllabus |
| চ্যাপ্টার | অধ্যায় | chapter |
| স্টুডেন্ট | শিক্ষার্থী | student |
| টিচার | শিক্ষক | teacher |
| হিন্ট | ইঙ্গিত | hint |
| প্র্যাকটিস | অনুশীলন | practice |
| ফ্রি | বিনামূল্যে | free |
| রেডি | প্রস্তুত | ready |
| ডিফিকাল্টি | কঠিনতা | difficulty |
| ক্লাস | শ্রেণি | class |

Avoid bookish, সাধু-adjacent words nobody says out loud: সংশোধনযোগ্য, সূচিবদ্ধ,
পুঙ্খানুপুঙ্খ, উপকরণ, প্রহর. Avoid literal calques — "word problems" is অঙ্ক or
ম্যাথ প্রবলেম, never শব্দসমস্যা.

**The Bangla is not a translation of the English string.** Compose it natively
with its own rhythm, carrying the same meaning. It often ends up a different
sentence shape entirely, and that is correct.

### Always the honorific আপনি

Every user-facing Bangla string addresses the reader as **আপনি / আপনার**, and the verbs
take the matching honorific forms:

| Write this | Not this |
|---|---|
| করুন | করো |
| নিন | নাও |
| দেখুন | দেখো |
| চান | চাও |
| যান | যাও |
| পারেন | পারো |
| লিখুন | লেখো |
| দিন | দাও |
| দেখান | দেখাও |
| পেরেছিলেন | পেরেছিলে |

**This applies to the student pages too.** An earlier draft used তুমি for students on the
theory that it read warmer to a school-age user, and it was rejected: Bangla uses
honorific pronouns for elders and strangers, and an application is a stranger. The whole
app was converted in one pass. Warmth comes from word choice and rhythm — ওদের over
তাদের, হিন্ট over ইঙ্গিত — not from dropping the honorific.

### One naming trap

The product is **ধী**. Its possessive form, ধীর, is indistinguishable from ধীর
meaning *slow*. **Never write ধীর.** Rephrase — "ধী-এর প্র্যাকটিস মোড", or
restructure the sentence. There is a comment about this at the top of
`strings.js`; leave it there.

## 8. Light and dark mode

```js
import { useTheme } from "../../shared/theme";
const { theme, setTheme, toggleTheme } = useTheme();   // "light" | "dark"
```

- Writes `data-theme="light|dark"` onto `<html>`, plus `color-scheme` so native
  form controls and scrollbars follow.
- Persists to `localStorage` under `dhi.theme`.
- **Follows the OS** (`prefers-color-scheme`) until the user makes an explicit
  choice, then stops following.
- `public/index.html` contains an inline script that reads `dhi.theme` and paints
  the attribute **before React mounts**, so the page never flashes white on its
  way to dark. Change the storage key or attribute name in both places — there is
  a comment in `theme/index.js` saying exactly this.

Dark mode matters more on your side than anyone's: a student practising at 11pm
is the person most likely to have it on. Check every screen in both themes. The
commonest failures:

- Text vanishing because a surface is hardcoded light while the text token flips.
- Two surfaces that were distinct in light mode collapsing into the same
  near-black. Assert that the computed `backgroundColor` of stacked surfaces
  actually differs — this exact bug shipped once already.
- A coloured button whose white label drops below 4.5:1 once the accent lightens
  in dark mode. The student login button handles it by switching to dark text on
  pink under `[data-theme="dark"]`.

## 9. Responsive and accessible

- Breakpoints in use: `1120px`, `900px`, `880px`, `620px`, `520px`. Follow them.
- Test at **390 × 844** and confirm
  `document.documentElement.scrollWidth === window.innerWidth`. Horizontal
  overflow on mobile is a bug and is easy to introduce with a wide grid, a long
  unbroken string, or a `min-width` on a field.
  **Assume most students are on a phone.** The chatbot especially: design the
  mobile layout first and let the desktop one be the adaptation.
- Use `100svh`, never `100vh`, for full-height sections — `vh` is wrong on mobile
  browsers with a collapsing address bar. A chat composer pinned to the bottom
  with `100vh` will sit under the browser chrome.
- Every interactive control needs a visible focus state. The convention is
  `outline: 2px solid var(--dhi-bloom); outline-offset: 3px`, or the bloom focus
  ring on inputs.
- Icon-only buttons need an `aria-label`, and the label comes from `t()`.
- Error messages get `role="alert"`.
- Decorative SVG gets `aria-hidden="true"`.
- **A streaming/updating chat log should be an `aria-live="polite"` region** so a
  screen reader announces new answers. None of the current code does this.
- Honour `prefers-reduced-motion: reduce` — drop transforms and long transitions.
  The hero video and logo splash already check it; typing indicators and
  message-entry animations must too.

## 10. The logo and brand components

The logo is a **tangram bird** — five flat triangles in pink, green, cyan, coral
and yellow — on a violet field, with the wordmark *Dhi AI*. It exists in three
forms and you should know which to reach for.

### `BrandLogo` — the navbar logo

```jsx
import BrandLogo from "../../shared/brand/BrandLogo";

<BrandLogo />                                  // links to /
<BrandLogo to="/dashboard" />
<BrandLogo onClick={() => navigate(-1)} />     // renders a <button>
<BrandLogo size="sm" />                        // sm | md (default) | lg
<BrandLogo tone="light" />                     // see below
<BrandLogo wordmark={false} />                 // mark only
```

It renders the bird on its violet tile plus the wordmark `ধী AI` / `Dhi AI`, and
it is already in **all six** navbars plus the landing page and footer. The tile
exists because the master artwork has no transparency — keying the violet out
would leave a fringe on every antialiased edge, and a tile survives both themes
from a single file.

**`tone`:**
- `auto` (default) — wordmark uses `--dhi-ink` and follows the theme. Use this on
  any surface that is itself themed.
- `light` — pins the wordmark to dark ink. For a surface that is **hardcoded
  white** and does not follow the theme. Every legacy page, including
  `ChatbotPage`, is currently in this category; without it the wordmark turns
  pale and disappears for anyone whose OS is in dark mode.
- `invert` — pins it to white, for a permanently dark panel.

> **When you convert `ChatbotPage` to real theme tokens, remove its
> `tone="light"`.** That single change is the signal that the page is done.

### `DhiMark` — the logo as vector

```jsx
import DhiMark from "../../shared/brand/DhiMark";
<DhiMark />                 // the six brand colours
<DhiMark tone="mono" />     // every piece in currentColor
```

Traced from the master artwork — each polygon is the exact convex hull of one
coloured region, mapped into a 550×432 box. No background, so it works at any
size on any surface. Used as the sticker on the teacher card, the watermark on
the admin panel, and the bird in the student login's night sky. **Prefer this
over the PNG whenever the mark sits on anything other than its own tile** — for
example an empty state, a loading state, or a "session finished" moment in the
chatbot.

### `LogoIntro` — the 2-second splash

The tangram lockup assembling itself, played once on the way into the auth
pages. **It is drawn, not played** — there is no `<video>` involved.

Why that matters, because it is the single most useful lesson in this codebase:
the master animation was shipped as a video, and it looked soft on screen no
matter how it was encoded. Measuring it explained why. The master is
`1920×1080` but tagged `sample_aspect_ratio 9:16`, so its *display* geometry is
1:1 — de-squeezed, the lockup inside it is only about **311 × 146 real pixels**.
On an ordinary retina laptop (1440 CSS px wide at DPR 2) the splash renders that
artwork at roughly 835 device pixels, a **2.7× upscale**. No CRF, preset or
container can add detail that is not in the file.

So the splash stopped using the video's pixels:

- **The five triangles are geometry.** Each polygon is the exact convex hull of
  one coloured region, traced off the 2000 px master artwork and expressed in the
  lockup's own coordinate space (931 × 433). Infinitely sharp at any size.
- **The wordmark is the one part that cannot be geometry**, so it is cut out of
  the 2000 px master at full resolution with a real alpha channel —
  `public/brand/wordmark.png`, 375 × 109 native, which is 3× the detail the video
  carried and enough to stay crisp past DPR 3.
- **The choreography is measured, not invented.** Each piece's entry offset,
  start time and travel were read frame by frame off the original animation
  (`PIECES` in `LogoIntro.js` carries the numbers), so it moves the way the
  designed version moves.

The behaviour around it is unchanged and worth knowing:

- `src/features/auth/AuthGate.js` is a **pathless layout route** wrapping all the
  auth routes in `App.js`. Because the same element stays mounted while the child
  route changes, the splash plays when you arrive from the landing page and
  **not** again when you move between the three login doors or over to signup.
  Deliberate: an intro is charming once and grating the third time.
- Skippable by click, Esc, Enter or Space. Under `prefers-reduced-motion` it
  shows the assembled mark briefly and moves nothing.

**The general rule to take from this:** before shipping any raster or video
asset, work out how many real source pixels will back each rendered pixel at
DPR 2. If the answer is less than one, it will look soft, and the fix is a better
source or vector — never a different encoder setting.

If you ever need to regenerate the wordmark cut-out from the master, the step
that matters is unpremultiplying against the known background so the glyphs
carry real alpha instead of being white-on-violet:

```python
# alpha = how far this pixel travelled from the brand violet toward white
a = max(0.0, min(1.0, max((c[i] - bg[i]) / (255 - bg[i]) for i in range(3))))
out[x, y] = (255, 255, 255, round(a * 255))
```

And if you add any video of your own: strip the audio track (`-an`) on anything
that autoplays — a muted autoplay video can never play its audio, so the track is
pure weight. That alone cut the landing hero from 5.1 MB to 2.9 MB. Also check
`sample_aspect_ratio` on every source; a file that looks correct in VLC (which
honours SAR) will be stretched in a browser if you re-encode it without
resolving the flag.

## 11. Your main job: the practice page

### What exists

`src/features/chatbot/ChatbotPage.js` — **863 lines**, the largest file in the
frontend. It is the original, un-redesigned code. The only change so far is that
the emoji logo in its navbar was replaced with `<BrandLogo tone="light" />`.

Supporting files:

```
src/shared/services/useChatSession.js   the API wrapper for all four modes
src/shared/services/useJobPolling.js    pollJobUntilDone(), used by quizSet
```

### What it does

A student picks **class → subject → chapter → topic**, then chooses one of four
modes. All four run against a persistent session (`chatbot_session_id` in
`localStorage`), and a sidebar lists previous sessions.

| Mode | What it does | API |
|---|---|---|
| **Q&A** | Free-form questions about the chapter, plus suggested starter questions and an "explain more" follow-up | `chatQaSamples`, `chatQaAsk`, `chatExplainMore` |
| **Practice set** | A batch of practice problems at a chosen difficulty | `chatPracticeGenerate` |
| **One by one** | The flagship: one question at a time, with `hint` → `answer` → `next`, and an explicit `end` | `chatSessionStart`, `chatSessionHint`, `chatSessionAnswer`, `chatSessionNext`, `chatSessionEnd` |
| **Quiz** | An MCQ quiz with per-question hints | `chatQuizGenerate` (async — see §12) |

`useChatSession` builds a `scope()` object (`subject_id`, `chapter_id`,
`topic_id`, `language`, `student_id`, `session_id`) into every request and
remembers the returned `session_id`. **Keep that contract intact** while you
rearrange the UI.

### What is wrong with it today

- A hardcoded white sticky navbar with a violet accent (`#7c3aed`) and hardcoded
  hex throughout ~40 inline style objects at the bottom of the file.
- **Emoji everywhere**, including a 2×2 "mode grid" whose cards are literally
  `icon: "📝"`, `"🎯"`, `"📋"` with hardcoded tile colours `#0ea5e9`, `#16a34a`,
  `#f59e0b`.
- **Emoji baked into the translated strings** — `"⚠️ কুইজ তৈরি করতে সমস্যা হয়েছে।"`,
  `"🔄 আবার চেষ্টা করুন"`, `"⏳ এখনো চলছে — একটু পরে আবার দেখো।"` There is even a
  line that strips a leading emoji back off at render time:
  `t.tabSet.replace(/^[^\p{L}]*/u, "")`. When you move these into `strings.js`,
  **strip the emoji out of the strings entirely** and let an SVG icon carry the
  meaning. Do not carry them across.
- Its own private `TXT` table and its own `language` state (see §6).
- No dark mode, no theme tokens.
- Bangla copy in the old register — it needs rewriting per §7. The pronouns have
  already been converted to আপনি app-wide, but the phrasing is still stiff.

### Suggested order of work

1. **Extract a shared app shell first.** All six app pages hand-roll the same
   sticky navbar from the same five copy-pasted style objects. Pull one
   `<AppNav>` into `src/shared/ui/` carrying the logo, breadcrumb, language
   switch, theme switch and account menu. Coordinate with Sunanda — she needs the
   identical component, and whoever builds it saves the other person the work.
   Everything you redesign before this exists is work you will redo.
2. **The mode picker.** Four clear, calm entry points with real SVG icons. This
   is the first screen a student sees and it currently looks like a toy.
3. **The conversation surface itself.** Message rhythm, the composer, the
   loading/thinking state, the hint→answer progression. This is the heart of the
   product and deserves the most care.
4. **The quiz view**, including its error and timeout states.
5. **The session sidebar**, including empty states.
6. **The student view of `/dashboard`** — coordinate, the file is shared.

### Places where real design thinking will pay off

These are opportunities, not chores:

- **The waiting state.** Generation takes a noticeable amount of time and the
  backend reports a human-readable `progress_stage`. Showing it — "looking
  through the chapter", "writing the hint" — turns dead time into something that
  feels considered. A bare spinner reads as a hang.
- **Hint before answer.** The whole pedagogical premise is that a hint comes
  first and the answer only if asked. Make that progression feel generous rather
  than withholding — the interface should feel like it is on the student's side.
- **Picking up where you left off.** Sessions persist. A student returning
  tomorrow should be met with that fact, warmly, not with an empty form.
- **Getting it wrong.** The moment a student answers incorrectly is the most
  emotionally loaded moment in the product. It must not feel like a red error box.
- **Mobile.** A student on a phone at night is the primary user. The composer,
  the keyboard, the scroll behaviour and `100svh` all matter more here than
  anywhere else in the app.

## 12. The backend contract — do not break this

Long work does not happen inside a request. The frontend **dispatches a job and
polls for it**. This was a recent, deliberate migration; keep it.

```js
import useJobPolling from "../../shared/services/useJobPolling";

const { data } = await someGenerateCall(...);        // returns a job id, not content
const { status, stage, result, error } =
  useJobPolling(data.job_id, "activeJob:quiz");
// status: IDLE | QUEUED | ... | SUCCESS | FAILED
// stage : a human-readable progress string from the worker
```

- Polls every 2s for the first 30s, then every 5s. Gives up at 15 minutes and
  returns `{ isTimeout: true }` — the UI should say "still running, check back",
  not "failed".
- `storageKey` must be unique per feature, so a page refresh resumes the right job.
- **`pollJobUntilDone()` is the plain-async version** for places a hook cannot
  run. `useChatSession.quizSet()` already uses it, because a hook cannot be
  called inside a plain async callback. Follow that pattern rather than forking
  the hook.
- `chatQuizGenerate` returns either `{ job_id }` (poll it) **or**, for a
  non-student caller, a plain `{ questions: [], message }` with no job id. The
  existing code branches on `data.job_id == null`. Preserve that.
- Ingestion is a separate contract with a different endpoint and field name; not
  your area, but it explains the `buildUrl` / `statusField` options on the hook.

### Other details worth knowing

- `language` in every call is the literal string `"bangla"` or `"english"`,
  defaulting to `"bangla"`.
- A `401` anywhere clears `localStorage` and hard-redirects to `/login` via an
  axios interceptor in `api.js`. Don't add a second redirect on top of it.
- Access tokens last 60 minutes and **there is no refresh endpoint implemented**,
  so a long practice session will simply end. Not yours to fix, but it explains
  surprise logouts — and it is worth handling gracefully rather than dumping the
  student on a login screen mid-question.
- `/chatbot` is role-gated to students in `App.js`
  (`<ProtectedRoute allowedRoles={["student"]}>`). `ProtectedRoute` only checks
  that an `access_token` exists in `localStorage` and reads the role from the
  stored `user` object — which is also why you can stub both for local UI work.

Full endpoint list: `src/shared/services/api.js`. Full backend description:
`PLATFORM_OVERVIEW.md` §7–11.

## 13. Verify visually, in a real browser

Screenshots are part of the work, not a nicety. A page that has only been
reasoned about is not finished — handing over an unexamined first draft reads as
low effort here.

The workflow used on the pages already built: headless Chrome driven by
puppeteer-core, seeding `localStorage` to pick language, theme and auth state,
then **asserting computed styles** rather than eyeballing.

```js
const puppeteer = require('puppeteer-core');
const b = await puppeteer.launch({
  executablePath: '/usr/bin/google-chrome', headless: 'new',
  args: ['--no-sandbox', '--disable-gpu'],
});
const p = await b.newPage();
await p.setViewport({ width: 390, height: 844, deviceScaleFactor: 2 });
await p.evaluateOnNewDocument(() => {
  localStorage.setItem('dhi.lang', 'bn');
  localStorage.setItem('dhi.theme', 'dark');
  localStorage.setItem('access_token', 'stub');   // ProtectedRoute only checks presence
  localStorage.setItem('user', JSON.stringify({ user_id: 1, name: 'Ayesha', role: 'student' }));
});
await p.goto('http://127.0.0.1:3000/chatbot', { waitUntil: 'networkidle0' });
console.log(await p.evaluate(() => ({
  overflow: document.documentElement.scrollWidth - innerWidth,   // must be 0
  bg: getComputedStyle(document.body).backgroundColor,
})));
await p.screenshot({ path: 'chatbot-bn-dark.png', fullPage: true });
```

Run the matrix: **bn/light, bn/dark, en/light, en/dark** at 1440px, plus 390px.
Five shots per screen, and it catches almost everything.

Three lessons learned the hard way on this codebase:

- `google-chrome --headless --screenshot` from the command line renders
  differently from a real page and will show you phantom clipping. Use puppeteer.
- A screenshot found a bug that reading the CSS did not: `.lp a { color: inherit }`
  has specificity (0,1,1) and silently outranked `.lp-cta-primary { color: #fff }`
  at (0,1,0), so every button label rendered dark. **Assert computed styles, not
  your intent.**
- Test autoplay and media **without** `--autoplay-policy=no-user-gesture-required`.
  Bypassing the policy hides exactly the failure you are trying to find.

## 14. Known traps

- **`src/shared/styles/index.css` still defines the old indigo palette** on
  `:root` (`--primary: #4f46e5`, `--bg`, `--text-primary`, …) plus legacy classes
  the old pages depend on: `.edu-input`, `.btn-primary`, `.btn-success`,
  `.btn-ghost`, `.form-label`, `.badge`, `.section-card`, `.glass-card`,
  `.app-header`, `.spinner`. Still live. Delete each only once nothing references
  it, and grep before you do.
- **`--dhi-*` tokens are global; the landing page's tokens are not.**
  `LandingPage.css` scopes its own `--surface`, `--ink`, `--accent` to `.lp`.
  Those names do not exist outside the landing page.
- **`useId()` is used for field/label pairing** in `fields.js` (React 18+). Don't
  hand-roll `id` strings alongside it.
- **The dev server serves `public/` live, but browsers cache video hard.**
  Hard-reload after replacing an asset or you will debug a file that is no longer
  there.
- **CRA lints on build.** An unused import is a local warning but fails a build
  with `CI=true`. Clean them up as you go.
- **`localStorage` keys already in use:** `dhi.lang`, `dhi.theme`,
  `access_token`, `refresh_token`, `user`, `chatbot_session_id`,
  `activeJob:<feature>`. Namespace anything you add.
