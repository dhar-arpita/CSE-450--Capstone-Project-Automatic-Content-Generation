**For:** the developer (and their Claude Code) picking up the teacher side of the
frontend.
**Assumes:** you have never opened this repo before.
**Companion doc:** [`docs/PLATFORM_OVERVIEW.md`](./PLATFORM_OVERVIEW.md) — the whole
system end to end (backend, AI pipeline, deployment). Read section 1 and 12 of it
before you start; the rest you can consult as needed.

## 0. What this document is

The landing page and the three login doors have already been rebuilt to a new
design language. The rest of the app — the pages a teacher actually works in —
is still the old, un-redesigned code. Your job is to bring the teacher surfaces
up to the same bar.

This document gives you the design system, the copy rules, the components that
already exist, the backend contract you must not break, and a page-by-page
description of what is there now and what needs to happen.

**Read sections 1–8 before writing any code.** They are the parts that are
expensive to retrofit.

## 2. Running it

```bash
cd frontend
npm install
npm start                 # http://localhost:3000
```

Create React App 5 / react-scripts, React 19, plain JavaScript. **No TypeScript,
no Tailwind, no component library, no CSS-in-JS build step.** Don't add one — the
project is small and the graders read the source.

Cold compiles on a modest laptop take 4–6 minutes. Be patient rather than
restarting it.

The backend defaults to `http://127.0.0.1:8000`; override with
`REACT_APP_API_URL`. To run the backend see `PLATFORM_OVERVIEW.md` §13. You can
do most frontend work without it — the pages render and fail gracefully.

## 3. The product, in a paragraph

Dhi (ধী — Sanskrit/Bangla for *intellect*) turns a chapter of the Bangladeshi
national curriculum into classroom material: worksheets, quizzes and study
notes, in Bangla or English. A teacher picks class → subject → chapter → topic,
sets difficulty and length, and gets a printable PDF. Students get a separate
practice mode that walks them through problems with hints. Generation is slow
(LLM + retrieval), so **everything heavy runs as a background job that the
frontend polls** — see §12.

## 4. The design language: forest + bubblegum

This is the part people notice. Two families:

- **Forest** — deep greens and a warm off-white paper. It carries structure:
  page backgrounds, body text, borders, primary buttons, dark panels. It is the
  calm, serious, editorial half.
- **Bubblegum** — a hot pink. It carries *emphasis only*: eyebrows above
  headings, the focus ring, the student-side primary button, small accents. It
  is never a background for large areas and never a second body colour.

Plus the **logo palette** — the six flat colours of the tangram bird
(violet, leaf, petal, sky, sun, coral). Use these for illustration and brand
moments, not for UI chrome.

**`--dhi-solid-bg` / `--dhi-solid-fg` is the important pair.** It inverts between
themes on purpose: a "filled" button is near-black on cream in light mode and
near-white on near-black in dark mode, so it always reads as the solid thing on
the page. Use it for primary actions and you get dark mode for free.

### The rule that keeps dark mode working

> **Never write a literal colour in a component.** No `#fff`, no `#0f172a`, no
> `rgba(0,0,0,.08)` in a `style={{}}` or a `.css` file.

Every colour comes from a token. If you need a colour that has no token, add one
to `tokens.css` **with both a light and a dark value**, and give it a semantic
name (`--dhi-surface-sunken`, not `--dhi-grey-100`).

The only exceptions already in the codebase are (a) permanently dark decorative
panels where a colour is part of an illustration, and (b) the pinned logo
wordmark colour (see §10), both of which are commented where they occur.

### What is explicitly rejected

This project's owner has a specific and strongly held bar. Work that looks like
this gets thrown away:

- ❌ Multi-stop gradients used as decoration — `linear-gradient(135deg, #4f46e5, #6366f1)`
  on a button or a logo tile. A single soft gradient used for *depth* (a night
  sky, a vignette) is fine; a gradient used because a flat colour felt boring is not.
- ❌ Glassmorphism blobs — floating translucent circles with `blur()`.
- ❌ Emoji standing in for icons. 🎓 📝 ⚡ 🎯 in a card or a button is the single
  clearest tell. Use the SVG icon set in `src/features/auth/icons.js`, or draw
  new ones in the same style (24×24 viewBox, `fill="none"`, `stroke="currentColor"`,
  `stroke-width: 1.7`, round caps and joins).
- ❌ Generic SaaS copy. "Everything you need, nothing you don't", "Supercharge
  your workflow", "Unlock the future". Placeholder writing is treated as a
  failure of craft, not a detail to fix later. See §7.
- ❌ Purple/indigo `#4f46e5`. That was the old palette; it is being removed.
- ❌ Drop shadows with a coloured tint (`0 20px 50px rgba(79,70,229,.15)`).

### What is wanted instead

Cinematic and editorial. The references the owner supplied were full-bleed
photographic heroes, minimal floating nav pills, large centred typography mixing
a serif display face with a sans body face, restrained pill buttons, generous
whitespace, and line-art illustration rather than stock graphics.

Look at these three pages before designing anything — they are the built
reference for this app:

```
src/features/landing/LandingPage.{js,css}     the hero and section rhythm
src/features/auth/AuthShell.js                three compositions, one language
src/features/auth/auth.css                    the form, button and field scale
```

## 5. Typography

Loaded in one request at the top of `src/shared/styles/index.css`.

| Role | English | Bangla |
|---|---|---|
| Body / UI | **Inter** | **Hind Siliguri** |
| Display / headings | **Instrument Serif** | **Tiro Bangla** |

Use the tokens `var(--dhi-sans)` and `var(--dhi-display)` — `tokens.css` already
swaps both families when `<html lang="bn">`, so you write the rule once.

**Bengali typesetting rules.** Getting these wrong is the fastest way to make
Bangla look machine-made:

- **No `letter-spacing`.** Tracking breaks conjuncts (যুক্তাক্ষর). Where a Latin
  eyebrow uses `letter-spacing: .15em`, the Bangla version must reset to `0`.
- **No `text-transform: uppercase`.** Bengali has no case; it does nothing, and
  the associated tracking damages the text.
- **More leading.** Matras sit above the x-height and descenders below it.
  Headings that are `line-height: 1.06` in English need ~`1.34` in Bangla.
- **Display accent stays upright.** `<em>` inside a heading is italic in
  Instrument Serif but must be `font-style: normal` in Tiro Bangla — a faux
  oblique on Bengali looks broken.
- Bangla renders larger at the same `font-size`; bump Latin sizes down slightly
  or Bangla up, per component.

The pattern used throughout:

```css
.au-eyebrow { text-transform: uppercase; letter-spacing: .15em; font-size: .7rem; }
html[lang="bn"] .au-eyebrow { text-transform: none; letter-spacing: .01em; font-size: .84rem; }

.au-title { line-height: 1.06; letter-spacing: -.02em; }
html[lang="bn"] .au-title { line-height: 1.34; letter-spacing: 0; }
```

## 6. Internationalisation

The whole app is bilingual, **Bangla first**.

```js
import { useI18n } from "../../shared/i18n";

const { t, lang, setLang, toggleLang } = useI18n();
t("auth.fields.email")     // "ইমেইল" or "Email"
t("auth.student.points")   // returns the array — map over it
lang                       // "bn" | "en"
```

- Every string lives in [`src/shared/i18n/strings.js`](../frontend/src/shared/i18n/strings.js),
  as two parallel objects `bn` and `en`. Add to **both**.
- `t()` takes a dot path. It falls back `bn → en → the key itself`, so a missing
  translation shows up as `auth.fields.email` in the UI rather than blank. If you
  see a dot path on screen, that is the bug.
- **There is no interpolation.** No `t("hello", { name })`. When a sentence needs
  a variable, either compose it in JSX from two keys, or — better, and what the
  existing code does — store one key per case. `auth.errors.wrongRole.student` /
  `.teacher` / `.admin` exist as three separate sentences precisely so each one
  reads naturally in Bangla, where word order differs from English.
- The choice persists in `localStorage` under `dhi.lang` and sets `<html lang>`,
  which is what drives all the `html[lang="bn"]` CSS above.
- **Bangla is the default** (`DEFAULT_LANGUAGE = "bn"`).

### The trap that will bite you

The legacy teacher pages each carry their own private string table and their own
`language` state:

```js
const [language, setLanguage] = useState("bangla");   // ← not "bn"
const t = TXT[language] || TXT.bangla;
```

and **that same value is also sent to the backend** as the generation language
(`generateWorksheet(..., language)` expects the literal strings `"bangla"` or
`"english"`).

When you migrate a page to the global `useI18n()`, keep the two concepts apart:

- **UI language** — `lang` from `useI18n()`, values `"bn" | "en"`.
- **Content language** — what the AI writes the worksheet in. A teacher may well
  want an English worksheet while using a Bangla interface. Keep it as its own
  piece of state and its own visible control, and map it to `"bangla" | "english"`
  for the API.

Defaulting content language to follow the UI language is a reasonable initial
behaviour, but it must stay overridable.

## 7. Copy

Copy is treated as design here, not as filler to replace later.

### English

Specific to this product, never interchangeable. Write about the actual thing
the software does: chapters of the NCTB curriculum, a worksheet before the next
period, a hint instead of the answer. Concrete beats clever.

The landing page headline is *"You teach the syllabus, now bring it to life in
their language."* That is the register — plain, warm, about the teacher's real day.

### Bangla — this is the part that goes wrong

The requirement is **প্রাঞ্জল (pranjol)**: lucid, easy-flowing, modern *spoken*
Bengali. Not formal, not literary, not translated.

**Bengali speakers mix English words into everyday speech constantly, and those
words should be written in Bangla script** — not in Latin letters, and not
replaced with formal Bengali equivalents.

| Write this | Not this | (means) |
|---|---|---|
| সিলেবাস | পাঠ্যক্রম | syllabus |
| চ্যাপ্টার | অধ্যায় | chapter |
| স্টুডেন্ট | শিক্ষার্থী | student |
| টিচার | শিক্ষক | teacher |
| হিন্ট | ইঙ্গিত | hint |
| প্র্যাকটিস | অনুশীলন | practice |
| ফ্রি | বিনামূল্যে | free |
| রেডি | প্রস্তুত | ready |
| ডিফিকাল্টি | কঠিনতা | difficulty |
| ক্লাস | শ্রেণি | class |

Avoid bookish, সাধু-adjacent words nobody says out loud: সংশোধনযোগ্য, সূচিবদ্ধ,
পুঙ্খানুপুঙ্খ, উপকরণ, প্রহর. Avoid literal calques — "word problems" is অঙ্ক or
ম্যাথ প্রবলেম, never শব্দসমস্যা.

Use warm pronouns. Copy addressed to a teacher about their students reads better
with ওদের than তাদের. Copy addressed to a student uses তুমি, not আপনি — compare
the student and teacher login pages.

**The Bangla is not a translation of the English string.** Compose it natively
with its own rhythm, carrying the same meaning. It often ends up a different
sentence shape entirely, and that is correct.

### One naming trap

The product is **ধী**. Its possessive form, ধীর, is indistinguishable from ধীর
meaning *slow*. **Never write ধীর.** Rephrase — say "ধী-এর প্র্যাকটিস মোড" or
restructure the sentence. There is a comment about this at the top of
`strings.js`; leave it there.

## 8. Light and dark mode

```js
import { useTheme } from "../../shared/theme";
const { theme, setTheme, toggleTheme } = useTheme();   // "light" | "dark"
```

- Writes `data-theme="light|dark"` onto `<html>`, plus `color-scheme` so native
  form controls and scrollbars follow.
- Persists to `localStorage` under `dhi.theme`.
- **Follows the OS** (`prefers-color-scheme`) until the user makes an explicit
  choice, then stops following.
- `public/index.html` contains a small inline script that reads `dhi.theme` and
  paints the attribute **before React mounts**, so the page never flashes white
  on its way to dark. If you change the storage key or the attribute name, change
  it in both places — there is a comment in `theme/index.js` saying so.

Every page you build must be checked in both themes. The commonest failures:

- Text that vanishes because a surface is hardcoded light but the text token flips.
- Two surfaces that were distinct in light mode collapsing into the same near-black.
  Verify the computed `backgroundColor` of stacked surfaces actually differs.
- A coloured button whose white label drops below 4.5:1 once the accent lightens
  in dark mode. The student login button handles this by switching to dark text
  on pink in dark mode.

## 9. Responsive and accessible

- Breakpoints in use: `1120px`, `900px`, `880px`, `620px`, `520px`. Follow them.
- Test at **390 × 844** (a normal phone) and confirm
  `document.documentElement.scrollWidth === window.innerWidth`. Horizontal
  overflow on mobile is a bug, and it is easy to introduce with a wide grid or a
  `min-width` on a field.
- Use `100svh`, not `100vh`, for full-height sections — `vh` is wrong on mobile
  browsers with a collapsing address bar.
- Every interactive control needs a visible focus state. The convention here is
  `outline: 2px solid var(--dhi-bloom); outline-offset: 3px`, or the bloom focus
  ring on inputs.
- Icon-only buttons need `aria-label`, and the label must come from `t()`.
- Error messages get `role="alert"`.
- Decorative SVG gets `aria-hidden="true"`.
- Honour `prefers-reduced-motion: reduce` — kill transforms and long transitions.
  Both the hero video and the logo splash already check it.

## 10. Brand components you should reuse

### `BrandLogo` — the navbar logo

```jsx
import BrandLogo from "../../shared/brand/BrandLogo";

<BrandLogo />                                  // links to /
<BrandLogo to="/dashboard" />
<BrandLogo onClick={() => navigate(-1)} />     // renders a <button>
<BrandLogo size="sm" />                        // sm | md (default) | lg
<BrandLogo tone="light" />                     // see below
<BrandLogo wordmark={false} />                 // mark only
```

It renders the tangram-bird mark on its violet tile plus the wordmark
`ধী AI` / `Dhi AI`, and it is already in **all six** navbars plus the landing
page and footer.

**`tone`:**
- `auto` (default) — the wordmark uses `--dhi-ink` and follows the theme. Use
  this on any surface that is itself themed.
- `light` — pins the wordmark to dark ink. Use it on a surface that is
  **hardcoded white** and does not follow the theme. All the legacy teacher pages
  are currently in this category; without `tone="light"` the wordmark turns pale
  and disappears for anyone whose OS is in dark mode.
- `invert` — pins it to white, for a permanently dark panel.

**When you convert a legacy page to real theme tokens, change its
`tone="light"` back to the default.** That is the signal that the page is done.

### `DhiMark` — the logo as vector

```jsx
import DhiMark from "../../shared/brand/DhiMark";
<DhiMark />                 // the six brand colours
<DhiMark tone="mono" />     // every piece in currentColor
```

No background, so it works at any size on any surface. Used as the sticker on
the teacher card and the watermark on the admin panel. Prefer this over the PNG
whenever the mark needs to sit on something other than its own tile.

### `LogoIntro` — the 2-second splash

Plays the animated tangram assembling, full-bleed, once, on the way into the
auth pages. You should not need to touch it, but know how it is wired:

- `src/features/auth/AuthGate.js` is a **pathless layout route** wrapping all the
  auth routes in `App.js`. Because the same element stays mounted while the child
  route changes, the splash plays when you arrive from the landing page and
  **not** again when you move between the three login doors or over to signup.
  That is deliberate — an intro is charming once and grating the third time.
- It is skippable by click, Esc, Enter or Space, has a 4.2s safety timeout, skips
  entirely under `prefers-reduced-motion`, and falls through if autoplay is refused.

### Brand assets

```
frontend/public/brand/logo-mark.png      512×512  the bird on its violet tile
frontend/public/brand/favicon.png        192×192
frontend/public/brand/logo-lockup.png    the full bird + wordmark
```

The splash is re-composed from the master so it can `object-fit: cover` the whole
viewport with no letterbox and no background colour to match. If you ever need to
regenerate it from a new master, this is the recipe — the padding is built from
the source's *own pixels* so there is no seam:

```bash
ffmpeg -i src/assets/logo_master_hd.mkv \
  -filter_complex "[0:v]crop=1440:1080:242:0[main];\
                   [0:v]crop=4:4:20:20,scale=1440:1440:flags=neighbor[bed];\
                   [bed][main]overlay=0:182,format=yuv420p[v]" \
  -map "[v]" -an -c:v libx264 -preset veryslow -crf 17 \
  -profile:v high -level 4.0 -pix_fmt yuv420p -movflags +faststart \
  public/videos/logo.mp4
```

The crop/overlay offsets centre the artwork and leave enough violet padding that
`cover` never crops the mark on any viewport from about 1:2.6 portrait to 5:1
landscape. If you change the canvas size, re-measure — don't guess.

## 12. The backend contract — do not break this

Long work does not happen in a request. The frontend **dispatches a job and polls
for it**, and this was a recent, deliberate migration. Keep it.

```js
import useJobPolling from "../../shared/services/useJobPolling";

// 1. dispatch — the POST returns a job id, not the content
const { data } = await generateWorksheet(topicId, userId, difficulty, n, sample, language, true);

// 2. poll — the hook survives a page refresh via localStorage
const { status, stage, result, error } = useJobPolling(data.job_id, "activeJob:worksheet");
// status: IDLE | QUEUED | ... | SUCCESS | FAILED
// stage : a human-readable progress string from the worker
```

- Polls every 2s for the first 30s, then every 5s. Gives up at 15 minutes.
- `storageKey` must be unique per feature (`"activeJob:worksheet"`,
  `"activeJob:quiz"`, …) so a refresh resumes the right job.
- Ingestion is the exception: it uses a different endpoint and field name. Pass
  `{ buildUrl: id => `/ingest/status/${id}`, statusField: "job_status" }` rather
  than forking the hook.
- `pollJobUntilDone()` is the plain-async version for places a hook cannot run.

**Show the `stage` string.** Generation can take a minute or more; a spinner with
no explanation reads as a hang. This is a real UX opportunity, not a chore.

### Other contract details worth knowing

- `language` in every generate call is the literal string `"bangla"` or
  `"english"`, and defaults to `"bangla"`.
- `refresh: true` bypasses the server-side cache. The Generate button sends it so
  "Generate" always means a fresh build; the cache is reached through Quick
  Answer instead. Don't silently drop the flag.
- `generateWorksheet` accepts an optional `sample_worksheet` file — a teacher can
  upload one of their own sheets and the output mirrors its style. This is a real
  differentiator and is currently buried behind a small text link on
  `GeneratePage`. Consider surfacing it.
- A `401` anywhere clears `localStorage` and hard-redirects to `/login` (an axios
  interceptor in `api.js`). Don't add a second redirect on top of it.
- Access tokens last 60 minutes and **there is no refresh endpoint yet**, so a
  session simply ends. Not yours to fix, but it explains surprise logouts.

Full endpoint list: `src/shared/services/api.js`. Full backend description:
`PLATFORM_OVERVIEW.md` §7–11.

## 13. Verify visually, in a real browser

Screenshots are part of the work, not a nicety. A page that has only been
reasoned about is not finished.

The workflow used on the pages already built — headless Chrome driven by
puppeteer-core, seeding `localStorage` to pick the language, theme and auth state,
then asserting computed styles rather than eyeballing:

```js
const puppeteer = require('puppeteer-core');
const b = await puppeteer.launch({
  executablePath: '/usr/bin/google-chrome', headless: 'new',
  args: ['--no-sandbox', '--disable-gpu'],
});
const p = await b.newPage();
await p.setViewport({ width: 1440, height: 900 });
await p.evaluateOnNewDocument(() => {
  localStorage.setItem('dhi.lang', 'bn');
  localStorage.setItem('dhi.theme', 'dark');
  localStorage.setItem('access_token', 'stub');        // ProtectedRoute only checks presence
  localStorage.setItem('user', JSON.stringify({ user_id: 1, name: 'Ayesha', role: 'teacher' }));
});
await p.goto('http://127.0.0.1:3000/generate', { waitUntil: 'networkidle0' });
console.log(await p.evaluate(() => ({
  overflow: document.documentElement.scrollWidth - innerWidth,   // must be 0
  bg: getComputedStyle(document.body).backgroundColor,
})));
await p.screenshot({ path: 'generate-bn-dark.png' });
```

Run the matrix: **bn/light, bn/dark, en/light, en/dark** at 1440px, plus 390px.
That is five shots per page and it catches almost everything.

Two lessons learned the hard way:

- `google-chrome --headless --screenshot` from the command line renders
  differently from a real page and will show you phantom clipping. Use puppeteer.
- A screenshot found a bug that reading the CSS did not: `.lp a { color: inherit }`
  has specificity (0,1,1) and silently outranked `.lp-cta-primary { color: #fff }`
  at (0,1,0), so every button label rendered dark. **Assert computed styles, not
  just your intent.**

## 14. Known traps

- **`src/shared/styles/index.css` still defines the old indigo palette** on
  `:root` (`--primary: #4f46e5`, `--bg`, `--text-primary`, …) along with legacy
  classes the old pages depend on: `.edu-input`, `.btn-primary`, `.btn-success`,
  `.btn-ghost`, `.form-label`, `.badge`, `.section-card`, `.glass-card`,
  `.app-header`, `.spinner`. They are still live. Delete each one only once
  nothing references it, and check with grep before you do.
- **`--dhi-*` tokens are global; the landing page's tokens are not.**
  `LandingPage.css` scopes its own `--surface`, `--ink`, `--accent` to `.lp`.
  Don't try to use those names outside the landing page.
- **`useId()` is used for field/label pairing** in `fields.js`. React 18+ only —
  fine here, but don't hand-roll `id` strings alongside it.
- **The dev server hot-reloads `public/` too**, but the browser caches videos
  aggressively. Hard-reload after replacing an asset.
- **CRA lints on build.** An unused import is a warning locally and can fail a
  CI build with `CI=true`. Clean them up as you go.
